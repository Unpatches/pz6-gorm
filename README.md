## Описание
ORM (Object–Relational Mapping) — это технология сопоставления объектно-ориентированных сущностей программы (например, структур в Go) с таблицами реляционной базы данных.

Зачем он нужен: 
1) Ускорение разработки
2) Безопасность
3) Поддержка миграций
4) Кросс-СУБД

GORM — это самая популярная ORM-библиотека на языке Go.

Основные возможности:
1)	автоматическая генерация таблиц по структурам (AutoMigrate);
2)	CRUD-операции: Create, First, Find, Save, Delete;
3)	фильтрация и сортировка (Where, Order, Limit);
4)	связи 1:1, 1:N, M:N (has one, has many, many to many);
5)	автоматическая подгрузка связанных данных (Preload);
6)	работа с транзакциями;
7)	хуки (функции, вызываемые до/после операций).

## Контрольные вопросы
1) ORM (Object–Relational Mapping) — это технология сопоставления
объектно-ориентированных сущностей программы (например, структур в Go)
с таблицами реляционной базы данных. Необходим для ускорения разработки, безопасности, поддержки миграций и для работы с СУБД.
Плюсы:
  - меньше шаблонного SQL, код компактнее.
  - создание/обновление схемы таблиц прямо из кода.
  - один и тот же код работает с PostgreSQL, MySQL, SQLite.
Минусы:
  - ORM может быть «медленнее» ручного SQL (особенно в больших проектах).
  - Для сложных запросов (агрегации, оконные функции) часто приходится писать сырой SQL.

2) 1:N - один ко многим, M:N - многие ко многим.
   Теги в работе:
     - primaryKey
     - type:text
     - not null
     - many2many:note_tags
     - size:50

3) Метод AutoMigrate:
   db.AutoMigrate(&User{})
     - создаст таблицу users, если её нет;
     - добавит новые поля, если они появились в структуре.
   Метода будет недостаточно, когда нужно удалять поля и менять типы (это нужно делать вручную или через внешние миграции).

4) Find/First загружают только данные основной модели, а Preload дополнительно загружает связанные данные
